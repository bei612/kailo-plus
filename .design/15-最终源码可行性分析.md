# 最终源码可行性分析

## 1. 总结论

Kailo 的目标设计不是“条件可行”。固定源码给出的确定结论是：

- 组件原语与已定位改动接缝分别为 `UPSTREAM_SUPPORTED` 或 `ADAPTER_REQUIRED`；两者均有固定 commit、文件和 symbol 依据。
- 统一 Secret 与 Temporal application Worker 的源码门禁（GAP-SEC-01、GAP-TMP-01）已于 2026-09-13 闭合：OpenBao 以固定 commit 进入 `.references`，其 namespace/KV v2/lease/audit/Agent 为上游能力（SF-OBA-01..09），Core 集成与投递为 `DESIGN_DEFINED`（DD-70/71/72）；`temporal-sdk-go` 以固定 commit 进入 `.references` 且 `v1.48.0` 与 Server `go.mod` 一致（SF-TMP-04、SF-TSDK-01..08），Application Worker 为 Kailo 自建代码（DD-69）。一期生产门禁改由 SS-AGW-ADMIN、SS-AGW-USAGE、SS-AGW-OIDC、SS-OMT-AUTH、SS-WEK-ASYNC-TRACE 的适配闭合与 GAP-LCM-01、GAP-WRN-01、GAP-AGW-01 决定。全部 active ResourceType 的 native 删除契约未由当前 SOURCE_SEAM 集合闭合（GAP-LCM-01），所以 Tenant 暂停设计有定义，销毁 Action 不得 active。
- `ADAPTER_REQUIRED` 不等于已实现。对应适配闭合并完成源码重验前，Action/Route/Tool/Workflow 不得 active。
- 能力状态仅使用 README 定义的四种；一期排除项另用 `EXCLUDED`，不另造中间状态。

## 2. 主链裁决

### 2.1 Web 认证与 Buzz 协作

| 链段 | 状态 | 固定依据 |
|---|---|---|
| AgentGateway OIDC login/session/local logout | `UPSTREAM_SUPPORTED` | authorization-code、PKCE、nonce/CSRF、issuer/audience/JWKS、加密 HttpOnly cookie、同源 POST 本地注销（SF-AGW-10） |
| claims→内网 BFF、logout 平台协同 | `ADAPTER_REQUIRED` | policy 顺序、CEL header transformation、Core PlatformSession 与 BFF stream 撤销（SS-AGW-OIDC） |
| Tenant→Community、Workspace→Channel、roster 数据模型与协议 | `UPSTREAM_SUPPORTED` | SF-BUZ-01/04/05/06 |
| Community 创建凭据链 | `ADAPTER_REQUIRED` | SS-BUZ-OPERATOR；部署级 RelayOperatorIdentity 与 Tenant CONTROL 分离 |
| OIDC Human→独立 Nostr identity→Relay event | `ADAPTER_REQUIRED` | SS-AGW-OIDC、SS-WEB-RELAY、SS-BUZ-SERVER-CLIENT；Nostr 私钥按 DD-72 托管（SF-BUZ-02/03） |
| Buzz Web BFF transport（仅 Web 端） | `ADAPTER_REQUIRED` | 不是单点 signer 替换；Browser 侧 concrete Relay client、query/subscribe/publish、NIP-42/NIP-98、media、user-state 和全部消费 hooks 的改造面为 SS-WEB-RELAY；服务端 NIP-42/NIP-98/query/stream/submit 的 Rust 接缝为 SS-BUZ-SERVER-CLIENT |
| Component Host 与运行时 release（Web + Desktop） | `ADAPTER_REQUIRED` | Buzz 当前 route/router/navigation/i18n 均静态；精确二开面为 SS-WEB-COMPONENT-HOST。Mattermost 直接证明 manifest→active fetch→script register→scoped registry→version reconcile/unload（SF-MAT-01/03/04）；其事件路径把 payload 当完整状态、只在重连时全量 reconcile（SF-MAT-06），是 DD-61 明确不采用的反例 |

AgentGateway 不产生 TenantMembership 或业务 permission；Core/BFF 只在已验证 subject 到达后解析 ExternalIdentity、邀请和 membership。Keycloak 是通用 OIDC issuer 的默认选择，不在 `.references` 内，本文不声明其内部行为或全局 logout。

Buzz Web 目前的收藏、静音和已读跨端同步依赖 Browser NIP-44 私钥（SF-WEB-05）。一期 Browser 无私钥（原生端本地持钥但按 DD-40 同样不另建第二份权威），因此 Relay kind:30078 路径明确停用；Core CollaborationUserState 是 `DESIGN_DEFINED` 的新权威，不声称 NIP-44 兼容。

Component Host 的可行性不等于 Mattermost 插件可直接移植。Mattermost 的 enable 是全局 config，初始化得到完整 store，server plugin 是本机 executable subprocess并获得宽 PluginAPI（SF-MAT-02/04/05）；这些与 Kailo 的 Tenant/Workspace、七项治理和独立 remote adapter 边界冲突，固定排除。Kailo 的 manifest、ComponentRelease/Binding 与 adapter 合同为 `DESIGN_DEFINED`；Buzz Web runtime Host 的源码改动为 `ADAPTER_REQUIRED: SS-WEB-COMPONENT-HOST`。

新增兼容 release 无需重发主体的结论有确定边界：它必须只使用当前 manifest schema、platform port、Host API、Adapter Protocol、canonical permission、Workflow kind 和三个 extension slot。它仍要求组件独立服务部署、Web artifact 交付/批准与 binding 对账。新增任一宿主/权威语义或 embedded/internal provider 代码仍需发布 Core/Buzz Web/Worker；因此本文不作“任意组件零开发热插拔”承诺（DD-56..64）。

### 2.3 Agent 记忆与会话恢复

| 链段 | 状态 | 固定依据 |
|---|---|---|
| Relay Channel/Thread/DM 协作历史 | `UPSTREAM_SUPPORTED` | event 先持久再 fan-out，ACP thread/DM 上下文有界且普通顶层 Channel 不取历史（SF-BUZ-07/20） |
| Codex durable AgentSession history/resume | `UPSTREAM_SUPPORTED` | ThreadStore create/resume/append/flush/read 与 app-server 分页 turn/item（SF-COD-09） |
| Buzz NIP-AE core/cold memory 协议与 Relay gate | `UPSTREAM_SUPPORTED` | addressable kind:30174、NIP-44、head/tombstone、author/owner filter（SF-BUZ-16/19） |
| Buzz ACP 新 Session core 注入与错误区分 | `UPSTREAM_SUPPORTED` | 最多 3 秒、confirmed absence 与 unreadable 分开、无中途刷新（SF-BUZ-17） |
| `SERVER_CODEX` memory adapter、Core Action 与 Memory 管理页 | `ADAPTER_REQUIRED` | 加解密/head 复用接缝 SS-BUZ-ENGRAM；平台 binding/Action/UI 见 `03`/`19` |
| 生产 memory 读写 | `ADAPTER_REQUIRED: SS-BUZ-ENGRAM` | Agent/CONTROL Nostr 私钥按 DD-72 托管于 OpenBao；服务端 engram adapter 复用 `buzz-core::engram` |
| Agent core replace 审批 | `DESIGN_DEFINED` | ApprovalWorkflow 由 DD-69 的 Application Worker 承接 |

一期长期记忆唯一权威是每 AgentInstallation 独立的 Buzz NIP-AE pair。Codex durable thread 是 Session 恢复权威而不是跨 Session 记忆库；WeKnora 是共享企业知识，不是 Agent 私有记忆。Codex 自动 Memory Pipeline 会形成 runtime-local DB/file 合并链，因此一期固定 `EXCLUDED`（SF-COD-10、DD-65）。

Buzz 原生 ACP 把 core 放入其系统 prompt，但 Kailo 一期是 `SERVER_CODEX`，不直接运行该 ACP pool。确定适配是复用 SS-BUZ-ENGRAM 的验签/解密/head 语义，将 core 作为低于 AgentVersion instructions 的明确分隔 context 交给 Codex；不把 Buzz ACP 的 prompt role 排序原样搬到 Codex（DD-67）。

### 2.4 授权、审批和任务工作台

- SpiceDB 的 Check/Lookup/Write/Watch/ZedToken 与 consistency 为 `UPSTREAM_SUPPORTED`（SF-SPZ-01/02）；`03` 的固定 `principal/tenant/workspace/resource/asset` schema 能承载全部组件。
- SpiceDB serve 强制 bearer preshared key；Temporal Server 提供 JWT system/namespace role，但空 auth 配置是 no-op，必须显式选择 default mapper/authorizer（SF-SPZ-03、SF-TMP-06）。两者只认证 Core/Worker service，不替代 Kailo 用户/Agent permission。
- Application Component 无须原生复制 Kailo Tenant/Workspace 表；ApplicationBinding 必须使用源码证明的隔离模式，Resource/Asset/owner/relationships 是统一授权入口。Platform Component 不伪造业务 scope，只通过 PlatformProviderBinding 实现已知 port。
- HUMAN Workspace scope 先要求 active WorkspaceMembership 或 workspace manage；AGENT scope 先要求 active Installation/Principal、workspace discover、Buzz roster 与 ChannelAgentBinding，再检查 Resource permission/Delegation。直接 owner 或 ToolBinding 不能绕过 scope（DD-46/50）。
- Resource home Workspace 与本次 Action execution Workspace 分离。Workspace Agent 调用 Tenant-level Agent/Skill/LLM Route 时继承父 Workspace，usage/audit 不丢 scope；Tenant 管理动作才固定 Workspace NONE（DD-54）。
- Delegation 不支持隐式通配；action+target/创建 Workspace 固定，首次 dispatch 以 operation 唯一计次。跨进程 ActionToken 是短期上下文，接收 PEP 仍 fresh Check（DD-49）。
- Temporal Server lifecycle 与 Schedule 为 `UPSTREAM_SUPPORTED`（SF-TMP-01/05）；Application Worker 不可省略，Nexus External target 也不能替代（SF-TMP-02/03）。
- ApprovalWorkflow、AgentTaskWorkflow、ComponentTaskWorkflow 和任务工作台为 `DESIGN_DEFINED`（GAP-TMP-01 已闭合，DD-69）；Worker 实现并通过重放回归前不得 active。Core DB、Buzz workflow 或组件 native task不得充当降级审批/Workflow 权威。

### 2.5 Capacity、Quota、Usage 与 Billing

- OpenMeter entitlement、credit、meter、usage、plan/subscription/invoice 与 LLM cost 为 `UPSTREAM_SUPPORTED`（SF-OMT-01）。
- OpenMeter 开源 server 只使用一个 static default namespace，v3 没有通用 API authentication（SF-OMT-06）。确定设计是同一 namespace 内一个 Tenant→一个 Customer、子 scope→subject；Core-only authentication 为 `ADAPTER_REQUIRED: SS-OMT-AUTH`，不声明 per-Tenant namespace。
- OpenMeter 无 action reserve，ingest 返回 202；Core QuotaReservation 是 `DESIGN_DEFINED` 的同步并发窗口，不复制账本（SF-OMT-02、DD-07）。STRICT_RESERVATION 只在全部该 Tenant+subject+meter producer 经 Core且动作有可证明上界时成立；它不是跨系统原子扣减（DD-51）。
- ingest/sink dedupe 默认关闭；固定 CloudEvent source/id/body 与两层 dedupe 是确定不变式（SF-OMT-03/04）。
- UsageEvent 显式固定 Tenant/Workspace/Customer/source；202 只到 ACCEPTED，按 ID/source 查到 `stored_at` 才 COMMITTED；`validation_errors` 由 OpenMeter 读时重算、不落库，只作配置告警；结算侧稳定结论读 charge/invoice 的 `validation_issues`；invoice finalized 另行查询（SF-OMT-07/08、DD-51）。CapacityLease expiry 也不等于 holder terminal，不能直接复用 slot。
- AgentGateway request log 只有配置 logging database 后可查询；DB batch 写失败后无重试并清批次（SF-AGW-06/09）。因此“查询已成功持久的 Gateway log”是 `UPSTREAM_SUPPORTED`，平台联合业务观测读模型是 `DESIGN_DEFINED`，完整 LLM billing usage 是 `ADAPTER_REQUIRED: SS-AGW-USAGE`。
- SS-AGW-USAGE 闭合前不创建模型 token/page/cost UsageEvent，不用 Codex/WeKnora 自报值补洞，不显示零用量或已结算。

| Wren | Python FastMCP Streamable HTTP、固定 project context、query tools/limits | 每 model version runtime=`DESIGN_DEFINED`；数据库只读 credential=`DESIGN_DEFINED`（DD-70/71）；native cancel=`BLOCKED: GAP-WRN-01` |

Wren 的 `strict_mode` 默认 false——默认配置下输入 SQL 解析失败会跳过 read-only AST 检查，且 planned SQL parse error fail open（SF-WRN-03）；active runtime 固定 `strict_mode=true`、`no_connect=false`、`allow_write=false`。数据库原生只读角色仍是写保护最终边界，`allow_write=false` 只关闭 Wren knowledge write tool（SF-WRN-01、DD-12）。

WeKnora 原生个人 Memory 为 `EXCLUDED`：其 tenant+caller scope 不含 Kailo AgentInstallation，一期仅使用 WeKnora enterprise knowledge（SF-WEK-16、DD-65）。

### 2.7 增量物化

CocoIndex Rust SDK、keyed diff、target pending/owner/generation、LMDB/App namespace 为 `UPSTREAM_SUPPORTED`（SF-CIX-02/03/04）。确定边界是：

- MaterializationBinding 固定 `coco_environment_ref/coco_app_name`；同一 pipeline version 的 run 只能回到同一 LMDB state，每个 binding 用独立 environment（`drop_state` 不释放 named-DB 目录项，SF-CIX-07）。
- state path 不可达时 run 失败，禁止换空 state 后把全部 source 当新增。
- run 成功判据是 `update_with_options` 返回 Ok **且**各组件 `num_errors == 0`：孤儿删除失败被引擎记录日志后吞掉、只留 tombstone，`update` 仍返回 Ok（SF-CIX-06）。
- purge 必须先跑一次空 desired set 的 update 让 target 收到 Delete，再 `drop_state`；Rust SDK 单独调 `drop_state` 不向 target 发 Delete（SF-CIX-06）。
- 周期权威是 Temporal Schedule；CocoIndex 没有独立 API/scheduler。
- Worker→Rust runner 调用链为 `DESIGN_DEFINED`（DD-69）；实现前不宣称 CocoIndex 已嵌入 Application Worker。
- Cells→WeKnora endpoint 组合与按 hash 归并的 create-new→ready→delete-old 语义为 `ADAPTER_REQUIRED: SS-CEL-MATERIALIZATION、SS-WEK-MATERIALIZATION`；WeKnora 新增内部 `ReplaceKnowledgeFile`，但没有公开 route，且不得原位改写被多个同内容 Cells node 共享的 Knowledge。GAP-SEC-01/GAP-TMP-01 已闭合，active pipeline 以该适配闭合为准。

WeKnora 已具有实体/关系图谱全链，EdgeQuake 会建立第二套摄取、图构建、检索和任务权威，因此 `EXCLUDED`（SF-WEK-05、SF-EDG-01）。

### 2.8 Business Observability、Audit、主题与 i18n

- Action/Audit、Buzz event、Temporal/native status、Codex refs、已持久 Gateway log 与 OpenMeter committed usage 足以形成受权业务 operation view；这项读模型是 `DESIGN_DEFINED`，不需要基础设施 telemetry 项目。
- 原始 Gateway log 只能展示成功持久的记录，不能证明计费全集完整；计费状态必须遵守 2.4。
- 所有 Governed Action AuditEvent 必有 Tenant；Tenant NONE 只用于 OIDC callback 后、Tenant 解析前的认证/Session事件。EvidenceRef 是带 authority/type/version-or-digest/sensitivity 的稳定引用，详情 fresh授权，不能保存临时 URL/token/payload（DD-52）。
- Buzz Web 与 Buzz Desktop 共用的 ThemeProvider/CSS variables、`en/zh-CN` AppLocale/MessageKey/t/getLocale 为 `UPSTREAM_SUPPORTED`；新增管理页是 `ADAPTER_REQUIRED: SS-WEB-01、SS-WEB-PRESENTATION`。主题偏好仅设备本地，locale 由浏览器解析且一期无语言设置；平台文案本地化，用户/业务内容保持原文。Cells/WeKnora/Wren 等原生 UI 不嵌入（DD-53）。
- ONLYOFFICE 只支持 launch-time theme/locale 映射；活跃 editor 不宣称实时换肤（SF-WEB-03、SF-OFF-07）。

### 2.9 Workspace 成员、跨 Tenant 转移与 Tenant 销毁

- Buzz relay/Channel roster 与 SpiceDB tenant/workspace relationship 的投影接缝已由 SF-BUZ-04/05、SF-SPZ-01/02 证明；Core TenantMembership/WorkspaceMembership 权威与 `PROVISIONING/ACTIVE/REVOKING/REVOKED/ERROR` 收敛合同为 `DESIGN_DEFINED`（DD-41/45）。建立/撤权是两个 ComponentTaskWorkflow kind，多投影运行链为 `DESIGN_DEFINED`（DD-69）；Core 的 `REVOKING` fail-closed 不等于投影已收敛。TenantMembership 终态还受 active Resource/Asset owner 转移门禁约束。
- Workspace 暂停/恢复确定映射 Buzz Channel archive/unarchive，并保留 Resource/Asset/owner；Buzz DELETE_GROUP 只软删除 Channel/discovery，故当前 Workspace 模型不含删除状态，也不注册 delete Action（SF-BUZ-15、DD-46）。
- 跨 Tenant 直接 relationship、binding、native ID 或 ExecutionContext 复用为 `EXCLUDED`。唯一合同是两段 `RESOURCE_EXPORT`/`RESOURCE_IMPORT`：源 Tenant ExportPackage Asset 经 HUMAN 下载，再在目标 Tenant 新 session 上传并创建新对象/新 owner。该领域合同与 Temporal 运行链均为 `DESIGN_DEFINED`（DD-42/69）；ResourceType 未有固定 export/import 格式与 API 源码证据时，`transfer_formats=[]` 且不暴露 Action。
- Tenant `SUSPENDING/SUSPENDED/RESTORING/DELETING/DELETED/ERROR`、TenantLifecycleSnapshot、distinct owner approvals、per-component ExternalExecution 和不可逆 dispatch 边界为 `DESIGN_DEFINED`（DD-43）。运行链为 `DESIGN_DEFINED`（DD-69）；但当前证据集没有闭合每个 active ResourceType/Binding/dedicated instance 的幂等 delete 与 terminal query（GAP-LCM-01）。因此可注册的生命周期管理仅到 fail-closed `SUSPENDED`；Tenant delete Action 不注册，`DELETING/DELETED` 不可达。
- PlatformProviderBinding 和 ApplicationBinding 的停用合同为 `DESIGN_DEFINED`（DD-44/62）；它们必须由 `ComponentTaskWorkflow(kind=COMPONENT_DISABLE, binding_kind=...)` 收敛 Schedule/relationship/route/tool/connection/native refs/usage/audit，运行链为 `DESIGN_DEFINED`（DD-69）；Workflow 对账完成前不把 Core `DISABLING` 报成已停用。

## 4. 紧凑运行边界

目标拓扑只包含 Buzz Client Surface 三端（Web 与 Desktop 含 Component Host）、Core/BFF（内含 Platform Port Router、Application Adapter Dispatcher 与 SS-BUZ-ENGRAM memory adapter）、应用组件 remote adapter、Buzz Relay、AgentGateway、SpiceDB、Temporal Server+Application Worker、OpenMeter、Codex runtime、Cells、DocumentServer、WeKnora、Wren 和 CocoIndex Rust runner。Core 内聚 Catalog/Admission/Projection/Reservation/Audit；对 SpiceDB/Temporal/OpenMeter/AgentGateway 使用固定 port client，不增加转发服务；Business Observability 是联合读模型。NIP-AE 复用现有 Buzz Relay，不新增记忆服务。Application Adapter 是组件 API 的松耦合边界，不取得新业务权威。Mattermost 不进入运行拓扑；也不存在独立 Agent Registry、Memory、Governance、Quota、Audit、Observability 或 CocoIndex control-plane 服务。

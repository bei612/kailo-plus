# 内置组件与交互场景

本文把 `02` 的源码能力映射到 `03`–`07`。状态严格使用 `UPSTREAM_SUPPORTED / ADAPTER_REQUIRED / DESIGN_DEFINED / BLOCKED / EXCLUDED`；状态描述的是当前固定源码与目标合同之间的确定关系，不表示实施进度。

本文分两部分，边界固定（DD-87/88/91）：

- §1–§3、§7 记录平台核心组件（Buzz Relay 与 Client Surface、Codex、AgentGateway、SpiceDB、OpenMeter、Temporal）的源码裁决，它们强集成、不可替换，其门禁属于平台门禁（`15`）。
- §4–§6、§8 与 §9.2 是**内置参考实现文档**：只描述一期内置的业务能力实现如何实现 `07` §2.4 的能力契约。它们不是平台前提，可被按同一能力契约准入的外部实现替换；其中的产品细节、接缝缺口与限制只阻断该实现自身的 ComponentRelease `APPROVED` 或 ApplicationBinding `ACTIVE`，不给平台新增实体、权限、Workflow kind、端口或门禁。零业务能力 binding 时平台完整可用。

## 4. `FILE_STORAGE`（含在线编辑）内置参考实现：Cells 与 ONLYOFFICE

Cells 与 ONLYOFFICE DocumentServer 作为一个“文件存储与在线编辑”能力组件部署单元交付：一个 ComponentRelease 声明 `implements[FILE_STORAGE@v1]` 并声明 `online_editing=SUPPORTED`（同时 `revision_query=SUPPORTED`），对平台是一个 ApplicationBinding（DD-103）。二者之间的 WOPI 是该组件内部集成，不是平台级连接，也不是两个业务能力服务之间的数据面直连（DD-90）。外部文件存储可声明或不声明在线编辑；在线编辑只作用于声明它的实现自己的 ContentReference，平台不在编辑器与文件存储之间建立数据通道，可替换的单位是文件存储实现本身；文件所属实现未声明 `online_editing=SUPPORTED` 时只显示元数据与受权下载（REQ-07、DD-90/103）。

| 能力 | 状态 | 源码裁决 |
|---|---|---|
| Cells Node/Version/action/share/upload/download → `FILE_STORAGE` 契约 | `UPSTREAM_SUPPORTED` | REST v2、data gateway、presigner（SF-CEL-01/03） |
| Cells native async job observe/control | `UPSTREAM_SUPPORTED` | BackgroundActionInfo/ControlBackgroundAction（SF-CEL-01/02） |
| Tenant dedicated binding | `DESIGN_DEFINED` | 独立实例、独立数据库与凭据（DD-93）；密钥按 release `secret_schema` 经 OpenBao 托管并经 Agent template 投递（DD-70/71） |
| `FILE_STORAGE` 契约的完整目录列举与按 revision 读取（供其他能力的接收方按 DD-89 自拉） | `ADAPTER_REQUIRED` | SS-CEL-MATERIALIZATION：受权 Lookup/GetByUuid/NodeVersions 与 version-specific 读取形成完整列举；native Workspace/root、node UUID、VersionId 为稳定身份与 revision，内部 broker 不作外部游标 |
| DocumentServer↔Cells 原生 WOPI（组件内部集成） | `UPSTREAM_SUPPORTED` | discovery/editor page/Check/Get/Put/document PAT 已相交（SF-CEL-05/07、SF-OFF-03） |
| Web/Desktop 通用 `SOURCE_BOUND_PROTOCOL` surface 的本实现 launch | `ADAPTER_REQUIRED` | 固定 origin WOPI form/iframe 接缝已确定（SF-OFF-03、SS-WEB-01） |
| WOPI 平台治理与兼容 | `ADAPTER_REQUIRED` | 默认 document PAT 不读取 ClientID、用户取自 Cells claims、`rw` 不读取平台决策；Platform Human/ProtocolSession/fresh PEP/fixed revision/origin/timestamp/evidence 与 DocumentServer copy/download 接缝均已定位（SF-CEL-11、SS-CEL-WOPI、SS-OFF-WOPI） |
| DocumentServer Tenant binding | `DESIGN_DEFINED` | 开源 package `multitenancy=false`，固定 dedicated instance；密钥按 `secret_schema` 与 DD-70/71 |
| Tenant 删除时的 native 删除 | `DESIGN_DEFINED` | 当前证据集未闭合幂等 delete 与 terminal query（GAP-LCM-01），release 声明 `retain_on_tenant_delete`，Tenant 删除时该 binding 的删除子流程撤 binding、撤凭据、保留审计并登记待人工处置，进入 `RETAINED_DECLARED`（DD-91） |
| “删除 20 人限制” | `EXCLUDED` | 当前 OS runtime 不存在该固定 gate（SF-OFF-04） |

本实现的门禁是 SS-CEL-WOPI 与 SS-OFF-WOPI（在线编辑能力，`online_editing=SUPPORTED` 的声明前提）以及 SS-CEL-MATERIALIZATION（`FILE_STORAGE` 完整列举读取能力）。release 只声明门禁已闭合的能力（DD-88）：在线编辑门禁未闭合时 release 声明 `online_editing=UNSUPPORTED`，门禁闭合后以后续 release 改为 `SUPPORTED`；不存在同一 binding 按能力部分激活的状态。这些门禁只阻断本实现的 release `APPROVED` 与 binding `ACTIVE`，不阻断平台（DD-91）。声明 `online_editing=SUPPORTED` 还要求本实现声明 `revision_query=SUPPORTED`，由 Cells NodeVersions 按 node UUID 查询当前 VersionId 提供（DD-90/103）。

ONLYOFFICE 部分只实现本组件 `FILE_STORAGE` 契约中的在线编辑条件能力（`file_storage.open_view@v1`/`open_edit@v1`），只作用于同一 binding 中 Cells 提供的 ContentReference，不拥有文件、ResourceType 或 owner。普通 Docs API callback 桥明确排除；查看/编辑/下载/复制/打印分别检查 `read/update/export`。完整合同见 `18`。

WeKnora 在本实现中同时承担知识库和其内置实体关系图谱；EdgeQuake 不作为一期内置参考实现并行接入。

本实现的知识导入按 DD-89 由接收方自拉：Tenant 或 Workspace 管理员在 WeKnora 能力组件的管理面（经 Component Host 露出）配置来源 `FILE_STORAGE` Resource；平台以 Governed Action 为本 binding 的 ServicePrincipal 写入来源 Resource 的 `reader` 关系，发起者须对来源 Resource 持有 `share`、对本知识库 Resource 持有 `update`。导入器每批经 Adapter Protocol `request_read_grant` 向 Core 申请，Core 以 SERVICE actor 准入后签发短期 ActionToken，来源实现的 PEP 校验令牌并再做 fresh `read` Check；导入器不持有来源实现的 native 凭据（`07` §8.2）。导入器的增量、去重、删除收敛与状态全部在本能力组件内部，平台不持有逐项状态、不建立 Schedule、不以 Workflow 编排；撤销 `reader` 关系后 Core 拒绝后续申请，来源方 PEP 拒绝后续读取。导入器的增量规则见 `13` §4。

WeKnora 对 `KNOWLEDGE` 契约 permission 的映射固定如下：

| `KNOWLEDGE` 契约 permission | WeKnora native route/capability | 执行条件 |
|---|---|---|
| `consume` | 检索与问答（含 `query_knowledge_graph`）；API key 使用 `retrieve` | KB read grant；只返回 answer/citation/受控 derived Asset |
| `read` | preview、检索；API key 使用 `retrieve` | KB read grant |
| `export` | `/:id/download`、`/knowledge-bases/:id/knowledge/batch-download` | API key 因 `RequireRole` 对 API key principal 短路，使用 `retrieve` capability 加 KB allow-list，不把它误写成 API key 必须有写权限。批量导出另受 200 文件、512 MiB 与进程级 4 slot 限制（SF-WEK-13/15） |
| `update` | ingest、reparse、delete | API key 使用 `ingest`，且目标 KB grant 满足写入角色 |

adapter 只以该 binding 的服务凭据（按 `secret_schema` 投递的最小权限 API key）调用 WeKnora，HUMAN 管理调用与本组件内部导入器都不另建 WeKnora native 账号，也不使用 HUMAN JWT 路径；HUMAN 与 Agent 的授权只在平台 PEP 完成（fresh SpiceDB Check 后才由 adapter 以服务凭据执行，DD-89/93）。任何 route 都按实际 handler 的 capability 与 KB grant 组合检查，不以执行 tenant 或空 capability 放行。

## 6. `DATA_QUERY` 内置参考实现：Wren

Wren 以 `implements[DATA_QUERY@v1]` 接入，release 声明 `versioned_model=SUPPORTED`，因此实现 `data_query.publish_version@v1` 条件键（DD-88/90）。语义模型与其发布版本是本实现按 `DATA_QUERY` 契约注册的 Resource 与不可变版本 Asset（`data_query.<kind>` 命名空间），不是 Core 实体（DD-90）；版本发布与下线由通用 `ComponentTaskWorkflow(kind=CAPABILITY_VERSION_PUBLISH)` 收敛。

| 能力 | 状态 | 源码裁决 |
|---|---|---|
| 固定 project 的 Python Streamable HTTP MCP runtime | `UPSTREAM_SUPPORTED` | FastMCP `/mcp`，ServeContext/engine 在启动时固定（SF-WRN-01） |
| query tools 与行上限 | `UPSTREAM_SUPPORTED` | run/dry-run/dry-plan/query-cube，默认 1000/最大 10000（SF-WRN-02） |
| SQL policy | `DESIGN_DEFINED` | active runtime 固定 `strict_mode=true`，但 planned SQL parse error 仍 fail open；最终写保护边界固定为数据库原生只读角色（SF-WRN-03、DD-12） |
| 数据库最终只读边界 | `DESIGN_DEFINED` | 必须投影数据库原生只读 credential；按 release `secret_schema` 经 OpenBao KV v2 版本托管并经 Agent template 投递到 Wren profile（DD-70/71/93） |
| 一个语义模型版本 Asset→一个 runtime/context | `DESIGN_DEFINED` | `RESOURCE_INSTANCE` 直接对应固定 ServeContext，通过 AgentGateway Streamable HTTP MCP target 调用（DD-12） |
| native query cancel | `BLOCKED: GAP-WRN-01` | 单 lazy connector、同步 query、无 MCP cancel tool（SF-WRN-04）。这是本实现的能力限制：release 声明取消能力 `UNSUPPORTED`，只影响本实现的取消语义，不阻断平台或本实现 binding `ACTIVE`（DD-91） |

Wren MCP 方法到 `DATA_QUERY` 契约 permission 的映射固定如下：

| MCP method | `DATA_QUERY` 契约 permission | 状态与执行点 |
|---|---|---|
| `run_sql`、`dry_run`、`query_cube`、`dry_plan` | 语义模型 Resource `execute` | ExtMcp policy server 逐方法执行；Wren 自身不做调用方 RBAC |
| `get_mdl`、`list_models`、`describe_model`、`get_data_source`、`list_cubes` | 语义模型 Resource `read` | ExtMcp policy server 逐方法执行；上下文工具在 Wren 内无条件注册（SF-WRN-06） |
| `store_query` | 无 | `EXCLUDED`；active runtime 固定 `allow_write=false`，不注册该工具（DD-12） |

浏览器与 Agent 都不直连 Wren。人发起的问数与 Agent 走同一条 Tool 链：Browser→BFF 语义命令→Admission→AgentGateway MCP→ExtMcp PEP→Wren runtime，Core 在这条链上是 AgentGateway 的 MCP client。Wren 是自托管实现，其 runtime 部署在平台运维域内、只对 AgentGateway 可达，因而可以自身作为 MCP target（DD-94(5)）。active runtime 固定 `no_connect=false` 与 `allow_write=false`；前者保证查询工具存在，后者只去掉 knowledge write tool，不代替数据库只读角色。Workflow cancel 只停止等待并屏蔽迟到结果。

## 8. CocoIndex：不是平台组件

CocoIndex 不是平台组件，不实现任何平台端口，不进入平台运行拓扑，也不由 Core/Worker 调用（DD-89）。如使用，它只作为 `KNOWLEDGE` 内置参考实现内部的增量导入实现：运行于该能力组件自己的运行体，状态自持，Core 不感知其状态、不为其建立 Schedule 或 Workflow。

|---|---|---|
| Rust SDK incremental/full/live/preview | `UPSTREAM_SUPPORTED` | `App::update_with_options/UpdateOptions`（SF-CIX-04） |
| keyed diff/delete reconcile 与 target pending/owner/generation | `UPSTREAM_SUPPORTED` | SF-CIX-02/03 |
| 持久增量状态 | `DESIGN_DEFINED` | 状态目录属于知识能力组件自身存储，不在 Core/Worker 运行体内（DD-93）。SDK 在 `db_path` 未设时静默回落相对路径 `./coco_state`，导入器必须始终显式传入绝对路径并在 run 前校验；每个导入配置使用独立 LMDB environment（SF-CIX-04/07） |
| 独立 scheduler/API service | `EXCLUDED` | 源码没有该运行面（SF-CIX-01）；周期触发由知识能力组件自身负责，平台不承接 |

CocoIndex 不接管 Cells version、WeKnora chunk/vector/graph、Buzz checkpoint、Gateway log cursor 或 Wren model。导入器的增量规则见 `13` §4。

## 9. 贯穿能力结论

所有应用组件和平台组件都必须在同一个 Governed Action 中携带 Tenant、Workspace、Authorization、Approval、Workflow、Capacity/Quota/Billing、Operation Audit 与 Business Observability；主题/i18n 贯穿所有用户可达前端。业务能力实现没有原生 Tenant/Workspace、没有独立原生前端或本身是 monolith 都不是拒绝接入的理由；ApplicationBinding 必须选择按 `07` §2.5 准入路径证明的隔离方式，后端通过独立 remote adapter 或经 binding 配置的标准协议接入，前端选择按能力类别渲染的 Host-native、获批准 remote module、通用 source-bound protocol surface 或 NONE。Platform Component 则必须通过 PlatformProviderBinding 绑定 Core 已知 port。不能证明隔离、身份、terminal、usage 或 presentation contract 的 action 不注册。

唯一前端壳是 Buzz Client Surface 三端（DD-74）。Cells、WeKnora、Wren、Temporal、SpiceDB、OpenMeter、AgentGateway 的原生管理 UI 不嵌入；内置参考实现的管理页使用按能力类别渲染的 `HOST_NATIVE`，承载端主体不含产品专名页面代码（`07` §4.1）。以后获批准 release 可通过固定 Component Host API 加载 `REMOTE_MODULE`，但不能直连 native management API或取得宿主 store。ONLYOFFICE 是通用 `SOURCE_BOUND_PROTOCOL` surface 的一个 `LAUNCH_MAPPED` 实现，主题/locale 在每次 WOPI launch 映射。

### 9.2 参考实现的治理映射细节

以下细节只属于内置参考实现，平台契约不依赖它们。

**ContentReference 与 ProtocolSession 映射。** `FILE_STORAGE` 实现中 ContentReference 的 `native_object_ref` 固定为 Cells node UUID，`native_revision` 固定为 Cells VersionId；ETag/ContentHash 只作校验证据，mtime 不作 revision。文件/文件夹默认只是 Cells 空间 Resource 的 native child，不单独登记文件 ResourceType。在线编辑的 ProtocolSession `kind` 为 `file_storage.edit_session`（本实现以 WOPI 编辑会话承载），`native_session_ref` 为 WOPI `usid`（取 ProtocolSession ID），`last_native_correlation_ref` 为 `X-WOPI-CorrelationId`，`token_revocation_key` 为 Cells PAT `RevocationKey`；细节见 `18`。

**能力组件规则。** ONLYOFFICE 部分不产生自己的长期 ownable 数据，所有 action 都指向 `FILE_STORAGE` 标准 ResourceType，短期 ProtocolSession 不升格为 Resource；owner 仍取目标 Resource/Asset 的 active HUMAN。

**语义模型版本。** Wren 的每个已发布语义模型版本 Asset 固定完整 `mdl.json` digest、数据库 profile SecretRef、`strict_mode=true` 与行限；runtime 与 AgentGateway Streamable HTTP MCP target 一对一绑定该版本。运行时不能切 project/profile，发布新模型不改写旧版本或旧 query evidence（SF-WRN-01/02/03、DD-12）。

**知识 Tool 传输。** WeKnora 自身不是 MCP server（仓库内 MCP 代码是它作为 client 调用外部的实现），因此本实现的 remote adapter 托管一个 Streamable HTTP MCP endpoint 并注册为 AgentGateway MCP target，形态与 Wren 相同，ExtMcp PEP 逐调用执行。普通检索与 `query_knowledge_graph` 都投影为同一 KnowledgeBase Resource 下的 `consume` Tool，不因工具名不同绕过 KB permission/result exposure（SF-WEK-05）。

**模型路由投影。** WeKnora 的模型配置行是 AgentGateway `llm_route` 在本实现中的投影，由管理员经本实现管理面配置指向 Gateway；平台不向 WeKnora 数据写入模型配置（DD-92）。

**容量。** 三个参考实现的动作 `capacity_policy` 全部为 `NATIVE`，不占用平台 `PLATFORM_SLOT`。DocumentServer memory guard 在编辑连接认证时把超限的新编辑文档改为 view（SF-OFF-04），它是 native 安全结果，不是 OpenMeter entitlement、permission deny 或需要被删除的 license gate；BFF 不做 launch 前容量预测。Wren runtime 与 WeKnora parser 同样只回报 native 容量结果。

**meter 来源。**

| 参考实现 | actual usage source | scope 归属 | 去重/计量键 |
|---|---|---|---|
| WeKnora Chat、Embedding、Rerank（`PLATFORM_LLM_ROUTE`） | SS-AGW-USAGE 闭合后的 durable Gateway usage | gateway user/group binding；存在 `traceparent` 时归因到 parent operation | stable request-log ID + provider 对应 token 或 page meter |
| WeKnora 知识导入 | WeKnora native task outcome | 本 binding 与导入配置所在 scope | native task ref + release 已登记的导入 meter |
| Cells 文件读取/写入 | 受权 stream bytes/native outcome | 空间 Resource + ActionExecution | native operation/ref + byte/op meter |
| ONLYOFFICE read/save | Cells WOPI GetFile/PutFile evidence + result revision | ContentReference 对应 Resource/Asset + operation | WOPI session/correlation + Cells read/write byte/op 以 Cells native ref 结算 |
| Wren query | query result row/limit、duration/native result | 语义模型 Resource + ActionExecution | query execution ref + row/time meter |

ONLYOFFICE 不产生“当前并发编辑人数”或“实际 EDIT mode”商业 meter：固定源码没有给平台可查询、可幂等归属到 Tenant/Workspace operation 的公开服务端并发/模式接口。WeKnora 或 Codex 自报 token 不形成计费事件。

**业务观测 evidence。**

| 参考实现 | 可展示的业务 evidence | 源码依据 |
|---|---|---|
| Cells | 空间/node/version/action/job ref、BackgroundAction status/progress/control result | SF-CEL-01/02 |
| ONLYOFFICE | ProtocolSession、Platform Human、WOPI session/correlation、requested/admitted mode、dirty/close、Check/Get/Put bytes/result、Cells base/result revision | SS-CEL-WOPI 补齐 dirty/close FileInfo 字段并在流式写入前执行 PEP；部分写入 500 进入 UNKNOWN、NodeVersions 对账（SF-OFF-07、SF-CEL-05/06/07/11/13/15） |
| WeKnora | KB/knowledge/task/graph/query ref、parse/reparse/cancel status、导入进度、Gateway log ref | SF-WEK-03/05/06 |
| Wren | 语义模型版本、query action、query hash/ref、row-limit/truncated、success/error | SF-WRN-01/02/03/04 |

组件内部没有源码接缝的状态不补造。Cells/WeKnora 的 queued/cancel accepted、Wren wrapper 停止等待都不能直接变成业务终态。ONLYOFFICE WOPI page 的 loading/dirty/close postMessage 只属于 Web 会话进度与 UI evidence，不能单独成为 permission、usage 或保存终态。

## 10. 确定交互结果

- OIDC 发消息：AgentGateway 完成认证，Core/BFF 完成 membership/permission 与 Nostr 代签；私钥托管按 DD-72；claims→BFF 投影（SS-AGW-OIDC）闭合前整条链 `ADAPTER_REQUIRED`。
- 零业务能力 binding：协作、Agent 回合与记忆、`PLATFORM_NATIVE` 工具、任务、审批、计量、审计全部可用；业务能力工具 effective 为 `NO_PROVIDER`，导航无业务入口（DD-87/92）。
- Agent consume 知识：只返回 answer/citation/受控 derived Asset；没有 `read/export` 时禁止原文、文件、raw chunk、SQL row 或模型定义。citation 以 ContentReference 回链来源，打开时重新授权。
- 知识导入（内置 WeKnora）：知识实现经授权并按批经服务读取边自拉 `FILE_STORAGE`；撤销 `reader` 关系后 Core 拒绝后续申请、来源方 PEP 拒绝后续读取；导入器只在完整列举成功时把缺失解释为删除，partial 列举绝不触发删除（`13` §4）。
- 数据查询取消（内置 Wren）：只停止平台等待并丢弃迟到结果，绝不显示 native cancelled。
- 文档保存（内置 Cells+ONLYOFFICE）：只有 Cells PutFile evidence 与 NodeVersions 的新 head revision 同时成立才显示 SAVED。
- OpenMeter 重试：同一 native source 使用同一 namespace/source/event.id/body，202 不等于 committed；`COMMITTED` 只看 `stored_at`，`validation_errors` 是读时重算值，不作终态判据。
- AgentGateway usage：原始 log tail 可展示已持久记录；SS-AGW-USAGE 未闭合时 LLM 计费显示 `BILLING_UNAVAILABLE`，不得显示零用量或已结算。

## 9. 贯穿能力结论

所有应用组件和平台组件都必须在同一个 Governed Action 中携带 Tenant、Workspace、Authorization、Approval、Workflow、Capacity/Quota/Billing、Operation Audit 与 Business Observability；主题/i18n 贯穿所有用户可达前端。Application Component 没有原生 Tenant/Workspace、没有独立原生前端或本身是 monolith 都不是拒绝接入的理由；ApplicationBinding 必须选择源码证明的隔离方式，后端通过独立 remote adapter 接 native API，前端选择 Host-native、获批准 remote module、source-bound protocol 或 NONE。Platform Component 则必须通过 PlatformProviderBinding 绑定 Core 已知 port。不能证明隔离、身份、terminal、usage 或 presentation contract 的 action 不注册。

唯一前端壳是 Buzz Client Surface 三端（DD-74）。Cells、WeKnora、Wren、Temporal、SpiceDB、OpenMeter、AgentGateway 的原生管理 UI 不嵌入；首批管理页使用 `HOST_NATIVE`。以后获批准 release 可通过固定 Component Host API 加载 `REMOTE_MODULE`，但不能直连 native management API或取得宿主 store。ONLYOFFICE 是 `LAUNCH_MAPPED` surface，主题/locale 在每次 WOPI launch 映射。

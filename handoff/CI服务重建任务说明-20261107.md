2. **在 CI 机上执行**：
   - 挂载 sda1 到 `/volumes/data`（按 UUID，`defaults,noatime`），只放冷数据；
   - 用 `tls.sh` 生成证书，然后执行 `install.sh <tls> 10.203.194.2`；

   - 证书私钥只在机器之间传递，不打印、不进 git。
3. **重写 CI 服务**，放进 `tools/ci/service/`，包括：
   - worker、client、`kailo-ci-control` 容器（Dockerfile/compose）；
   - systemd 单元（`kailo-ci-worker`/`-feedback` 的 `.path` 和 `.service`，`Slice=kailo-ci.slice`）；
   - `config.json` 模板和幂等的 install 脚本。

   **接口必须兼容现有调用方**。从这些地方反推契约：
   - `tools/release/orchestrator.py` 的 CI 类：`submit` 返回 32 位十六进制 job ID；`status` 和 `wait --timeout` 返回 JSON，退出码 0、1、124 分别表示成功、失败、超时；`logs --tail`；
   - `tools/release/node.py` 读取的 config 键（grep `cfg[`、`cfg.get(`）；
   - `/usr/local/bin/kailo-ci`，即 `docker --context kailo-ci exec kailo-ci-control python3 /ci/client.py "$@"`；
   - 手册和交接文档里列出的子命令：submit（check/build/deploy/docs 等）、check-step（lint/verify/contract/migrate/trace/docs/supply）、gen、artifact、status、logs、wait、list、cancel、retry、handoff、clean。

   其他要求：
   - 源码只从 GitHub 取；**支持分支 commit**，即 origin 上任一分支 head 能到达的 commit；
   - 每条 lane 一个并发，有内存和磁盘准入；
   - 发布源树放在 `<sources>/<commit>/apps`；
   - 构建目标与镜像的映射从 `tools/release/release.yaml`、`*/fork/upstream.yaml`、`tools/check.sh`、`tools/check.Dockerfile`、`tools/build-upstream.sh` 读取；镜像推到 `127.0.0.1:55000`。

## 2. 从零认识 Kailo：产品是什么

Kailo 是企业级多人、多 Agent 协作平台。人和 Agent 在频道、项目、任务和工作流中协作，动作共同经过身份、scope、权限、审批、额度预留、审计及外部副作用对账。它不是把几个开源后台加链接，也不是重新写一套简化聊天产品。

### 2.1 强集成底座与可替换业务服务

| 层 | 组成 | 权威与边界 |
| --- | --- | --- |
| 协作与客户端 | Buzz Relay、Web、Desktop、Mobile | Relay 保存协作内容及执行协作面准入；三端提供完整原版体验 |
| 治理内核 | 单体模块化 Rust Core/BFF、Go Application Worker | Core 管理平台元数据、准入、事务及投影；Worker 用 Temporal 执行既定工作流，不直写 Core 数据库 |

## 4. 核心架构与一次动作如何经过治理

### 4.1 身份和三端传输

OIDC 提供外部身份，Core 按 issuer/subject 维护统一身份及 scope 映射。Buzz roster、组件原生角色、Temporal Search Attribute、客户端选中状态都不是平台成员权威。

| 客户端 | 协作数据平面 | 管理平面 |
| --- | --- | --- |
| Web | Browser 经公开入口/BFF；Core 代签访问 Relay，不向浏览器下发 Nostr 私钥 | 经 BFF；Browser 不持平台或组件管理凭据 |
| Desktop | 本机持自己的 Nostr 私钥，直连 Relay，由 Relay 准入 | 仍经 BFF |
| Mobile | 同 Desktop 的身份边界，Flutter 原生消费者 | 仍经 BFF；不渲染组件宿主入口 |

Tenant、Workspace、Channel、Project、资源 owner 与 binding 范围必须按现有实体合同解析。不能回退默认租户、猜 scope、共享 signer 或把用户的多会话当作多个独立人类账号。

### 4.2 治理路径与事务边界

完整动作的大致路径如下；这是理解既有实现的索引，不是新增统一执行器的设计：

```text
真实页面 / 人 / Agent / Schedule / callback
  → 可信身份和 ExecutionContext
  → scope guard + 当前资源授权 + binding/generation/投影前置
  → 既有所需审批 + quota/capacity reservation
  → Core 事务内持久意图、执行引用、audit/outbox
  → Temporal / Relay / AgentGateway / 组件 Adapter 的既有执行消费者
  → 原生 observe、用量关联、终态证据及结果暴露前再授权
  → 确定终态，或 UNKNOWN 后沿原引用对账收敛
```

外部副作用前持久化 `ActionExecution`、`Operation`、`ExternalExecution` 或既定等价引用。跨服务用 outbox、幂等、observe/reconcile，不引入分布式事务或另一套公共账本。审批通过不保证执行时仍有权限、额度或有效 binding。

Core 只保存平台权威元数据、引用和准入/预留/投影/审计，不复制消息、文件、chunk、SQL row 或 prompt/response 正文。正文权威留在源服务；经授权的客户端和 Agent 可以消费服务返回内容。“Core 不复制正文”不能误解为所有客户端都不能读内容。

Worker 是 Go/Temporal 执行者，通过 Core service API 做 fresh admission、投影、audit/usage；不直写 Core DB、不复制授权算法。既定 Workflow 包含审批、AgentTask、ComponentTask；具体种类以设计及 registry 为准，不按产品另造 Workflow。

### 4.3 最容易破坏的三条性质

1. **Fail closed：** 身份、scope、权限、binding、secret、投影、用量关联、终态证据任一必要事实缺失，就拒绝/阻断/保持待对账；不降级为默认身份或绕过校验。
2. **结果不明不等于失败：** HTTP 超时、202、cancel accepted、Workflow 投影更新、进程退出都不能单独证明业务终态。UNKNOWN 保留原意图和原执行引用，不新建 ID 盲目重放，不伪造成功、失败或零用量。
3. **单一权威：** 不新增第二份 Agent 注册表、权限、quota、计费、审计、记忆、工作流或同步编排权威。

六类错误固定在 `apps/06` §4：

| 分类 | 含义与处理 |
| --- | --- |
| `DENIED` | 身份/scope/permission/delegation/exposure 不满足，不能自动重试绕过 |
| `BLOCKED` | 已设计阻断或能力未开放，不注册对应入口、动作或工具 |
| `PRECONDITION` | binding/secret/projection/generation/readiness 不成立，修复事实后再进入 |
| `LIMIT` | quota/capacity/rate/大小上界，按既有策略背压 |
| `CONFLICT` | 版本/revision/head/幂等或并发冲突，用户处理或对账介入 |
| `UNKNOWN` | 外部结果不明，待对账且保留证据入口，禁止盲目重放 |

### 14.1 用户要求的快推进，不是减少正确性

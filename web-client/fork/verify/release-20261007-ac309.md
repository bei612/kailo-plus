## Web 构建的实际失败与修正

首次原 `tools/build-upstream.sh web-client` 退出 1，原输出：

```text
sh: patch: not found
npm error code 127
```

固定 node:24-alpine 的 build 阶段缺少原 virtua postinstall 的工具依赖。
Dockerfile 增加带持久 apk 缓存的 `apk add patch`，不把工具加入 Caddy 运行镜像。
第二次原入口实际安装 patch 2.8-r0 后，完整补丁 dry-run 又真实失败：

```text
checking file lib/index.cjs
Hunk #1 FAILED at 35.
checking file lib/index.js
Hunk #2 FAILED at 39.
npm error code 1
```

两次均没有生成或部署 Web 产物；原失败日志保留，未跳过 postinstall。

随后在受限 SDK 中取锁定 virtua 0.49.3 官方 tarball，实核 SHA-512 与原 lock
一致。GNU patch 2.8 复现同样失败：原包 cjs 第 40 行、js 第 44 行的行尾
ASCII 空格不在原补丁删除行中。原 postinstall 的正向 dry-run/apply 与反向
幂等检查统一使用 `-l` 处理空白，不修改原补丁或忽略实际代码差异。
三文件 apply 退出 0，反向检查退出 0 且文件摘要未变；主动改变 cjs 函数参数
为未知语义后，完整 postinstall 真实退出 1；恢复原字节后反向检查再次退出 0。
原输出在 `custom-emoji-scope-20261007.3o81Ot/virtua-pristine.log`、
`virtua-whitespace-restored.log`、`virtua-unknown.log`。Web 输入为上述固定提交
加这两处打包修正，不能仍标成未经修改的 ac309 输入；后续按实际 source digest
登记，不重复构建没有变化的 Core/Worker。

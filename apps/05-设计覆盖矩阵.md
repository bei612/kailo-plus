# 设计覆盖矩阵

本文件把 `.design` 的每一个实体、设计决策、要求与接缝分配到唯一的首次交付 Stage，使 `AGENTS.md` 规则 3 的追溯纪律与 `03-验证发布与验收门禁.md` 的追溯检查从第一天起可执行。

分配表达的是“该对象首次成为可验证实现约束的 Stage”，不是它唯一被触碰的 Stage；后续 Stage 仍可扩展同一对象。任何进入实现的能力必须能在本文件找到归属，找不到即说明设计或路线缺一环，按 `04-上游适配与升级.md` 的先改设计流程处理。

本文件是派生视图，不引入新语义。与 `.design` 冲突时以 `.design` 为准。

## 1. 覆盖自检

每次修改 `.design` 或本文件后必须重跑三项计数。计数只统计对应小节**表格行内**的标识符，不统计表下的说明段落；任一不等即为缺口：

```text
.design/03 中形如 `实体名(` 的声明数        == §2 各表格行内出现的实体名去重数
.design/02 中 DD-* 定义行数                 == §3 表格行数
.design/02 中 SS-* 定义行数                 == §4 各表格行内出现的接缝去重数
```

当前基线：实体 84、`DD-*` 93、`SS-*` 24、`V-REQ-*` 22、`V-SCN-*` 79。`V-SCN-*` 的 Stage 映射在 `02-纵向交付路线.md` 各 Stage 与能力扩展的验收映射中维护，本文件不重复。

归属单元按 `02-纵向交付路线.md` §1.0 的两部分划分：平台核心链 Stage 0–5 与平台一期收口，以及可选、互不依赖的能力扩展 EXT-FILE、EXT-KNOW、EXT-DATA。归属到能力扩展的对象只作用于该能力类别的契约或其实现，不得成为平台核心链任一门禁的前提（`DD-87`、`DD-91`）。

| 能力扩展 EXT-KNOW（参考实现增强项，不阻断 `ACTIVE`） | `SS-WEK-ASYNC-TRACE`、`SS-WEK-LLM-CTX` |
| 一期不交付 | `SS-CEL-EDITOR` |

`SS-AGW-ADMIN` 首次闭合于 Stage 3：Platform Port Router 写 AgentGateway ConfigResource 就已经需要 Core-only 认证，Stage 5 的 Agent/Tool 投影复用同一接缝。

`SS-CEL-*`、`SS-OFF-*`、`SS-WEK-*` 全部是内置参考实现的 binding 激活门禁，只阻断该实现的 ComponentRelease `APPROVED` 或 ApplicationBinding `ACTIVE`，不进入平台核心链任一退出门禁或一期生产总门禁（`DD-91`）。`SS-CEL-MATERIALIZATION` 归 EXT-FILE：它是文件存储参考实现为接收方提供完整列举读取的接缝，平台不以它编排同步（`DD-89`）。`SS-WEK-ASYNC-TRACE`、`SS-WEK-LLM-CTX` 只影响成本归因精度（`DD-92`）。

`SS-CEL-EDITOR` 一期不闭合：`.design/02` 已判定它只能返回 `PreSignedURL`，不足以表达 Buzz Web 所需的结构化 editor config。

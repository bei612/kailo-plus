# 上游适配与升级

## 1. 目的

Kailo 组合多个成熟上游，但不直接在 `.references` 中开发。该目录只提供固定源码证据和更新差异；可发布改动位于本工程的 fork、patch queue、adapter 或 driver 中。

升级目标是安全吸收新能力与修复，同时保持设计权威、协议兼容、权限边界、Workflow replay 和数据可恢复性。

## 2. 每个上游的版本记录

每个进入运行拓扑的项目维护一份机器可读 baseline manifest，字段与校验规则以 `06-工程基线规范.md` §2 为准，记录上游地址、证据 commit、实现基线 commit 与两者差异说明、patch series 及其 digest、artifact digest、关联的 `SF-*`/`SS-*`、兼容性证据与 owner。

`evidence_commit` 对应 `.design/02`；`implementation_base_commit` 对应实际 fork。两者不同时必须有已复核的差异说明，不能暗示设计证据自动覆盖更高版本。

## 3. 四种上游关系

| 关系 | 适用对象 | 升级方式 |
|---|---|---|
| 原样依赖 | 已由 `UPSTREAM_SUPPORTED` 覆盖的服务/库 | 固定版本，核验所依赖行为在新版本仍成立后升级 |
| 上游 fork/patch | Buzz、buzz-web、AgentGateway、OpenMeter、Cells、Codex 等 `SS-*` | patch queue 重放，逐接缝复核 |
| Remote Adapter | Cells、WeKnora、Wren | 保持 native 服务，升级 adapter 合同与 capability map |
| Reference only | Mattermost、EdgeQuake 等 | 只在设计证据受影响时重验，不进入发布物 |

## 4. 差异驱动升级流程

### 4.1 接收差异

`.references` 由独立维护流程在一次明确更新中刷新。实现工程只读取：

- old/new commit；
- upstream changelog；
- 文件与符号 diff；
- `.references/UPDATE_TASKS.json`；
- 更新后的源码阅读手册作为导航。

不得让实现 CI 自动 `git pull` 或改写 `.references`。

### 4.2 影响分类

先按路径与符号命中现有 `SF-*`、`SS-*`，再沿引用关系扩散到 `DD-*`、实体、Action、Workflow、`V-SCN-*` 和实现模块。每项差异归入：

1. 无合同影响；
2. 源码事实文字更新，产品合同不变；
3. 接缝签名或行为变化，需要 patch/adapter 调整；
4. 上游新增能力，需要新的设计证据与产品决策；
5. 安全或兼容性破坏，阻断升级。

上游新增 endpoint、feature 或配置不会自动成为 Kailo Resource、Action、Tool、Route、meter 或 Workflow。

### 4.3 先改设计，再改实现

若 `SF-*`、`SS-*`、`DD-*`、`GAP-*` 或能力状态变化：

1. 在固定 new commit 上复核路径、符号和完整语义；
2. 先修改 `.design/02`，再同步权威文档与验证矩阵；
3. 完成 `.design` 全量自检；
4. 更新本目录实施追溯与 compatibility 结论；
5. 最后修改 fork/patch/adapter 与其验证。

设计不变的升级也必须记录“重验通过”，不能只写依赖版本号。

### 4.4 重放 patch

每条 patch 必须关联一个具名 `SS-*` 或已批准的构建/运维修复。重放顺序：

1. 在隔离分支把 patch 应用到 new base；
2. 人工审查目标 hook 的调用顺序、错误语义、默认配置和安全上下文；
3. 运行上游自身测试，并核验 Kailo 登记的每个接缝仍然成立；
4. 更新 patch series digest 与 provenance；
5. 不再需要的 patch 只有在上游行为已被源码证据完整覆盖时删除。

冲突能自动解决不等于语义兼容；每个被触碰的 `SS-*` 都要重新验收。

## 5. 组件升级合同

### Platform provider

- 建立新的 immutable ComponentRelease；
- 建立新的 PlatformProviderBinding generation；
- 校验 service identity、config/secret、protocol、readiness、governance 和 read-back hash；
- 只把新调用切到新 generation；旧调用保留原 generation；
- 失败时不回退到未批准 provider。

### Application component

- adapter 先对 new native version 运行 handshake 与 capability tests；
- 新 ComponentRelease 固定 adapter、native compatibility、schema 与 web artifact digest；
- 建立新的 ApplicationBinding generation 并完成 scope/route/tool/observability 对账；
- 正在运行的 Action/Workflow/ExternalExecution不换 generation；
- rollback 同样建立新 generation，不篡改历史 release。

### Embedded driver

新 driver 代码必须通过 Core/Worker 发布。manifest 只能选择已编译 registry 中的 exact driver key，不能在运行时上传动态库或 executable。

### Protocol peer

WOPI 等协议升级必须以双端矩阵验证 request/response、header、timestamp、error、retry、security 和 terminal evidence。只验证 happy path 不允许升级。

## 6. 必须重验的高风险面

- AgentGateway OIDC policy 顺序、header transformation、cookie、CORS、admin auth、MCP auth mode、usage durability 与 proxy header hygiene；
- Buzz Relay ingest signer、membership、operator API、NIP-11 limit、timestamp drift 与 NIP-AE head；
- buzz-web Relay client、Service Worker、CSP、route/navigation、theme/i18n 与 Component Host；
- Codex protocol feature flag、environment、approval、MCP reload、thread resume、usage correlation 与 runtime storage；
- Temporal Server/Go SDK version、Workflow replay、Update validator、Start policy、Schedule 和 history limits；
- SpiceDB permission/check/lookup cursor 与 consistency token；
- OpenMeter auth、dedupe、CloudEvent、stored/validation/billing terminal；
- Cells WOPI auth、PutFile partial write、timestamp、version evidence；
- DocumentServer request filtering、ipfilter、WOPI launch/header/callback；
- WeKnora tenant/grant/task/LLM trace、dedupe、graph 与 readiness；
- Wren MCP registration、read/write policy、runtime context、timeout/cancel；
- CocoIndex state path、named DB、diff/delete、batch failure isolation。

## 7. 升级验证矩阵

每次升级至少执行：

1. 上游 commit 与 tree 可解析；
2. 所有受影响 SF/SS 路径和符号存在且语义复核；
3. patch queue 可重放且 diff 只覆盖登记接缝；
4. schema/API/Adapter/Host compatibility；
5. Workflow replay 与 migration 演练；
6. 受影响 `V-SCN-*` 的端到端与故障场景核验；
7. Tenant/Workspace 隔离、撤权、secret、header/token 的安全核验；
8. usage/audit/operation correlation 完整性；
9. artifact digest、SBOM、provenance 与签名；
10. 新旧 generation 灰度、回滚与 retained execution 观察。

任一高风险接缝无证据或验证失败时，升级停止在隔离分支；当前生产 baseline 不变。

## 8. 文档与手册保护

源码阅读手册是人工维护资产，不接受无损性未知的整篇自动重写。更新流程必须：

- 先保存旧版 byte count、line count、heading set 与 hash；
- 只针对 upstream diff 修改受影响章节；
- 对大幅缩短、标题丢失、证据路径减少设置硬失败门禁；
- 保留人工正文，生成内容写入独立候选文件后再做结构化合并；
- 合并前输出逐节 diff，禁止以摘要替换完整手册；
- 完成后校验全部代码路径、commit、标题、链接和更新记录。

实现工程只消费经过复核的差异，不运行会覆盖 `.references` 手册的生成任务。

## 9. 升级完成定义

- `.design` 与实现 baseline manifest 指向明确且可解析的 commit；
- 所有受影响 SF/SS 已重验，能力状态与 exposure 一致；
- patch/adapter/driver 的 artifact 与 tests 可追溯；
- migration、Workflow replay、binding generation 与 rollback 已验证；
- production gate 未被弱化；
- 更新记录清楚说明吸收、拒绝和延后的上游变化。

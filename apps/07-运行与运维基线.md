# 运行与运维基线

本文件把分散在 `.design` 各篇的运行前提汇总为可执行清单，并固定实施工程在可观测性、数据保留、容量与运维手册上的最低要求。

它不重定义任何设计语义。每条不变式都标注设计来源；与来源冲突时以 `.design` 为准。它也不选择具体产品——数据库、编排、日志后端等仍由 `00-实施总纲.md` §6 的 ADR 决定。

## 1. 部署前置不变式

以下条件在 `.design` 中分散登记，任一不满足都会静默削弱安全或可用性边界。它们必须成为部署校验的一部分：Core 启动时或 binding 进入 `ACTIVE` 前主动核验，核验失败即拒绝启动或拒绝激活，而不是写在文档里靠人记住。

| 组件 | 不变式 | 违反后果 | 设计来源 |
|---|---|---|---|
| OpenBao | 部署拓扑配置 auto-unseal | raft 单集群每次重启处于 sealed，而 SecretRef 不可读时 binding 不得 active，整平台无法冷启动。该条保障冷启动可用性而非安全边界，按 §2 本地开发拓扑可用脚本化解封替代，分片存放于受控投递面；部署描述则必须配置外部密钥源 | `DD-70` |
| OpenBao | 配置中不出现 `disable_mlock`，且宿主禁用或加密 swap | Nostr 私钥与 ActionToken 私钥明文驻留内存可被换出。上游已移除 mlock：配置里出现 `disable_mlock` 且为 `false` 时进程直接拒绝启动，保护点因此从进程配置移到宿主 swap 策略。前半条可由部署描述校验，后半条只能在宿主层核验 | `SF-OBA-10`、`DD-70` |
| OpenBao | 在服务端配置中声明至少一个 audit device | 零 device 时 audit broker 的 fail-closed 分支被短路，取用不留痕。该版本拒绝经 API 启用，只接受声明式配置，且块标签必须给满 type 与 path 两个 | `SF-OBA-06`、`SF-OBA-11`、`DD-70` |
| OpenBao | `server -dev` 不进入任何 active 拓扑 | 内存 storage 加固定 root token | `DD-70` |
| OpenBao | KV v2 的 `max_versions` 显式设定，且大于任何 active binding 所钉版本与当前版本之间的最大差值 | 默认只保留 10 个版本，超出的**静默**删除。SecretRef 钉的是具体版本，被裁掉就永远读不回来；而 SecretRef 不可读时 binding 不得 active——于是一个还在用的 binding 会因为别处的几次轮换而永久失效，且失效点离原因很远。实测：同一路径写到第 18 版时最旧可读版本已是第 9 版 | `DD-70`、`.design/03` §9 |
| Temporal | 显式配置 default claim mapper 与 authorizer | `authorization` 留空时所有调用方获得 system admin | `SF-TMP-09`、`DD-69` |
| Temporal | 同时定义并以 `--service=internal-frontend` 启动 internal-frontend，且 `publicClient` 为空 | 只开 authorizer 而不给内部系统 Worker 单独入口时，它们因无 claims 被拒，集群起不来；仅在配置中声明而不显式启动同样无效 | `SF-TMP-10` |
| Temporal | namespace retention 固定并登记为运行前提 | 终态证据随 history 一起过期消失，`NotFound` 无法区分"未启动"与"已过期" | `.design/06` |
| Buzz Relay | `require_relay_membership=true`，且**由 NIP-11 观测核验**而不只看配置 | 成员校验短路为 open relay，roster 只是展示事实，撤权在 Relay 侧不生效。该条可从 `/info` 的 `supported_nips` 是否含 `43` 直接观测：上游仅在「配了稳定 relay 私钥且开启成员校验」时才广告 NIP-43，因此它等价于这两条前置同时成立（`SF-BUZ-35`）。Core 在 `TenantBuzzBinding` 进入 `ACTIVE` 前记录该观测值，不采信配置自述 | `SF-BUZ-26`、`SF-BUZ-35`、`.design/09` |
| Buzz Relay | `allow_nip_oa_auth=false` | 不在 roster 中的 pubkey 可凭 owner attestation 通行 | `SF-BUZ-26`、`.design/09` |
| Buzz Relay | `require_auth_token=true`，且 `RELAY_OWNER_PUBKEY` 为有效 64 位十六进制 | 前者默认 false 时 REST API 绕过令牌认证，而 REST 面同样承载业务读写；后者在成员校验开启时缺失会直接拒绝启动 | `SF-BUZ-30` |
| Buzz Relay | 运行 Kailo 打过 `SS-BUZ-GOVERNANCE` 补丁的构建（不是上游发布镜像），且 `BUZZ_MEMBER_EVENT_KINDS` 显式设定为已交付能力所需的 kind。运行期开关，重启生效；未设定即上游行为 | 未设定或跑上游镜像时，任何成员可自建 Channel、自加入与加人、读写非 private Channel、开 DM、定义由 Relay 执行的 workflow（`SF-BUZ-37`）——原生端持钥直连时 Workspace 隔离整体失效。列表多一个 kind 就多开放一种成员可发布的协作能力，因此它随能力分配（`apps/05` §7）一起变更 | `SF-BUZ-37`、`SS-BUZ-GOVERNANCE`、`DD-80` |
| Buzz Relay | `BUZZ_NIP43_RECONCILE_INTERVAL_SECS` 显式设定并作为成员投影的收敛上界登记 | relay-level roster 唯一的读取面是 best-effort 重建的 NIP-43 快照事件，其重建在「同一秒内回到此前出现过的成员集合」时因事件 id 相同而整事务回滚，快照停留在过期值上；修复只来自该周期作账（默认 60 秒）。不登记这个值，撤权对账的最坏用时就没有上界，`REVOKING` 会无限期悬停 | `SF-BUZ-34`、`DD-41`、`DD-45` |
| Kailo BFF | `BFF_STREAM_READMIT_SECONDS` 显式设定并作为撤权对**已建立流**生效的上界登记 | 请求/响应路径每次都重新解析身份，撤权对下一个请求立刻生效；但一条已经建立的 SSE 流不再经过那条路径。不登记这个周期，被撤权的人能继续收到事件而没有上界 | `.design/03` §4.1、`SS-AGW-OIDC` |
| Kailo BFF | `PUBLISH_RESULT_SETTLE_SECONDS` 不小于 Relay 的时间漂移窗口（900 秒，编译期常量）。运行期开关，重启生效 | 小于窗口时，一条结果不明、在窗口剩余时间内仍会被 Relay 接受的消息会先被判为「确定未送达」，审计与实际相反 | `SF-BUZ-40`、`DD-81` |
| Kailo BFF、Browser | 注销必须先调 BFF 再调网关 logout | 网关的 logout 是短路的，请求根本不到后端（`SF-AGW-21`），先调它就再也没机会告诉 Core，PlatformSession 会一直留到过期 | `SS-AGW-OIDC`、`SF-AGW-21` |
| SpiceDB | preshared key 经环境变量或文件投递 | 命令行 flag 在启用 tracing 时随 OTel resource 导出 | `SF-SPZ-04`、`.design/09` |
| AgentGateway | 每条 MCP 认证配置 `mode: strict`、非空 `audiences`、显式 required claims | 省略 `audiences` 即关闭 audience 校验；非 strict 模式放行无 JWT 请求 | `SF-AGW-11`、`DD-49` |
| AgentGateway | 原生端 listener 的 `jwtAuth` 显式 `mode: strict`、非空 `audiences`、不保留令牌；浏览器 listener 移除 `x-kailo-client-surface`。运行期开关，配置文件即时生效 | 上游 `mode` 缺省 `optional`，不带令牌的请求直接放行；省略 `audiences` 即关闭 audience 校验；保留令牌会把用户凭据转给 BFF；浏览器若能自报 `x-kailo-client-surface` 就能打开只对原生端开放的入口 | `SF-AGW-24`、`DD-78` |
| IdP | 原生端客户端登记为公开客户端：PKCE `S256`、redirect 只允许本机回环、访问令牌带 audience `OIDC_NATIVE_AUDIENCE`；`BFF_CLIENT_KEY_PROOF_WINDOW_SECONDS` 与 `BFF_CLIENT_KEYS_PER_PRINCIPAL` 显式设定 | 允许任意 redirect 等于把授权码交给任何注册了该地址的应用；令牌不带该 audience 时原生入口全部拒绝。持钥证明的时间窗是截获证明可被使用的上界，设备上界缺失则一人可无限登记公钥 | `DD-78`、`DD-79`、`core/verify/native-identity.md` |
| Kailo BFF | `BUZZ_RELAY_NATIVE_URL_TEMPLATE` 形如 `ws[s]://{host}[/path]`：authority 恰好是 `{host}`，不另带端口或 userinfo；Relay 对外用非默认端口时，端口写进 `BUZZ_COMMUNITY_DOMAIN`，成为每个 Community host 的一部分。代入后在原生客户端所在网络可解析、可达（DNS 与 TLS 覆盖全部 Community host）。运行期开关，重启生效 | 形状不符时 Core 拒绝启动。模板里另带端口时，客户端发出的 Host 带端口而 Community host 不带，Relay 回通用 404（`SF-BUZ-41`）；主机名不是 Community host 时原生端连进的是别的 Community 或连不上——Relay 按 Host 绑定 Community | `SF-BUZ-32`、`SF-BUZ-41`、`DD-75`、`DD-78` |
| AgentGateway | 每条 MCP RBAC 规则集非空 | 空规则集对所有方法、所有资源放行 | `SF-AGW-16` |
| AgentGateway | admin router 不暴露给 Browser、Agent 或 Tenant admin | 同一平面含覆写配置、改监听端口与关停进程的接口 | `SS-AGW-ADMIN` |
| AgentGateway、OIDC 提供方 | issuer 与 redirect 使用带点的主机名，不用单标签名 | HTTP 客户端的 cookie 引擎普遍不为单标签主机名保存或发送 cookie，授权码流会在提交凭据一步失败并报 `Restart login cookie not found`，失败点距真实原因很远 | `SS-AGW-OIDC` 的核验记录 |
| buzz-web | CSP 只为固定 DocumentServer origin 放宽 `frame-src`/`form-action`，`script-src 'self'` 不变 | 不放宽则 Office surface 打不开；放宽 `script-src` 则远程模块的字节约束失效 | `SF-WEB-06`、`DD-30`、`DD-60` |
| buzz-web | 组件 artifact 路径位于 Service Worker 的 `/app/` scope 之外 | SW 对 `/assets/` 永久 cache-first，会钉死旧 generation | `SF-WEB-07` |
| Buzz Desktop | 发布产物必须以启用 `system-keyring` feature 编译，并在构建产物中留下可核验的 feature 记录 | 该 feature 关闭时 nsec 私钥回落为 `0o600` 明文文件，不再受 OS keyring 保护；这是编译期而非运行期开关，运行时无法纠正 | `SF-DSK-02`、`DD-75` |
| Buzz Desktop / Buzz Mobile | 两端直连的 Relay 必须 `require_relay_membership=true` | 原生端本地持钥、Core 不在其发布路径上，roster 校验是协作数据平面唯一的准入执行点；关闭即等于 open relay | `SF-BUZ-26`、`DD-75` |
| Buzz Mobile | 构建产物不含任何 WebView 组件宿主或 editor surface 入口 | `REQ-21` 禁止以内嵌 WebView 作为组件与编辑能力的替代路径，出现即绕开分级并引入第二套组件运行时 | `REQ-21`、`DD-74` |
| DocumentServer | `ipfilter` 精确允许该 Tenant 的 Cells host，不使用默认 allow-all；相关配置组合登记进 binding config digest | JWT 内 URL 走 direct path，默认私网过滤不构成 WOPI SSRF 边界 | `SF-OFF-10`、`.design/18` |
| WeKnora | 渲染出的 `SYSTEM_AES_KEY` 恰好 32 字节 | 长度不符时加密函数原样返回明文并报成功，provider 凭据明文入库 | `SF-WEK-12`、`DD-71` |
| WeKnora | ApplicationBinding 只接受配置了 Redis 的实例 | Lite 模式下任务队列移除是固定 no-op，取消语义不成立 | `SF-WEK-03`、`.design/08` |
| Wren | 每个 SemanticModelVersion runtime 位于只有 AgentGateway 可达的网络边界内 | 其 MCP 端点没有任何认证，可达即可经只读凭据取得全部查询能力 | `SF-WRN-06`、`.design/09` |
| CocoIndex | 始终传入绝对 `db_path`；每个 MaterializationBinding 使用独立 environment | 缺省时 SDK 静默回落相对路径；共用 environment 会因 named database 不回收而耗尽目录项 | `SF-CIX-07`、`.design/03` |
| Codex Runtime | 每 Installation 独立 `CODEX_HOME` 且其中不配置任何 local environment；client 在 `initialize` 声明 `experimentalApi` | 前者是本地执行面的承重封堵；后者缺失时 `environments: []` 被拒绝 | `DD-15`、`SF-COD-03` |

清单随 `.design` 演进。新增上游或新增 binding 类型时，必须同步问一遍：它有没有"默认值不安全"或"缺省即关闭"的开关。

## 2. 本地开发环境

目标是让任一工程师在一台机器上跑通一条纵向切片，而不是复刻生产拓扑。

- 上游服务使用 `04-上游适配与升级.md` 的 baseline manifest 所固定的版本，以 artifact 或镜像引入，不从 `.references` 工作树构建。
- 本地拓扑必须保留 `01-工程结构与模块边界.md` §8 的网络边界形状：Browser 只到达公开入口，BFF 只接受身份投影，管理面不可直达。本地可以简化副本数与持久化，不可以简化边界。
- §1 的部署前置不变式在本地同样生效。降低其中任何一条都会让本地验证失去意义——尤其是 Relay 成员校验、MCP audiences 与 RBAC 规则集。
- 提供一条统一命令完成格式、静态检查、contract 检查、迁移演练与追溯检查，与 CI 使用同一入口；其余验证按需接入同一入口。
- 开发用 secret 也经受控投递面取得，不在仓库、环境文件或脚本中出现明文。
- 名字按生产的形状解析，不为本地另开别名：IdP 以 issuer 里的主机名与端口在本机发布（`KEYCLOAK_PORT` 与 issuer 端口一致），令牌的 `iss` 才与 BFF、Temporal 配置的 issuer 相等；IdP 与 Relay 的主机名、核验时临时开通的 Community host 经 `/etc/hosts` 指向本机，Community host 由核验脚本在开通后加入、结束时删除。

## 3. 可观测性实现要求

`.design/14` 定义的是受权只读的业务视图。本节规定实现侧必须产生什么信号，以及什么绝对不能进入信号。

必须发出：

- 每个 Governed Action 的开始与终结，带 `operation_id`、Tenant、Workspace、actor、ActionDefinition 版本与终态 reason code；
- 每次外部副作用的 dispatch 与观察结果，带 ExternalExecution 引用与 native 状态原值；
- 每个 Workflow 的状态跃迁投影写入结果，以及投影落后的显式度量；
- 每次 usage 发布与其 committed 确认，以及缺口计数；
- 每个 binding、generation、projection 的对账结果与不一致计数；
- 每类 §1 不变式的校验结果，作为启动与激活的门禁信号。

禁止进入任何日志、指标标签或链路属性：

- 消息正文、文件内容、chunk、SQL 行、prompt 与 response、Office 文档内容；
- secret 值、token、cookie、私钥、PAT；
- 高基数的自由文本。标签只用封闭枚举与稳定 ID。

链路关联以 `operation_id` 为主键贯穿 Core、Worker、adapter 与组件。对目前无法透传关联上下文的跳，按 `.design` 的对应接缝结论记为不可归因，并在业务视图中显示确定状态，不以推测补齐。

## 4. 数据保留、备份与恢复

权威分散在多个系统，因此不存在"一次备份全部"。恢复演练必须按权威逐个进行。

| 权威 | 保存内容 | 保留与备份要求 |
|---|---|---|
| Core 数据库 | scope、owner、binding、Action/Operation、Approval 投影、ExternalExecution、Audit、Outbox、SecretRef locator | 平台恢复的主对象；需要按时间点恢复能力；Audit 与 Usage 记录不可删改 |
| OpenBao | secret 版本与 lease | 独立备份与恢复流程；恢复顺序先于依赖它的一切 binding |
| Temporal | Workflow history | 受 namespace retention 约束，不是长期档案；终态必须已投影进 Core |
| Buzz Relay | Community、Channel、消息、NIP-AE 记忆 | 协作与记忆权威，按其自身机制备份 |
| SpiceDB | schema 与关系 | 授权关系权威。只经其批量导出与导入 API 做逻辑备份与恢复：revision 是 Postgres 事务 id，SQL 级转储恢复到另一集群后关系全部不可见（`SF-SPZ-06`） |
| IdP | 用户及其稳定 subject | Core 的 ExternalIdentity 以 (issuer, subject) 对应到人；subject 变化即所有人无法登录。与 Core 数据库同一时间点备份 |
| Cells | 文件字节与版本链 | 文件权威 |
| WeKnora | 知识与索引 | 可由 Cells 重新物化，但重建代价需评估 |
| OpenMeter | committed usage 与账单 | 计费权威，不可由平台重算覆盖 |
| CocoIndex | 增量状态 | 丢失会导致全量重建；每 binding 的 state 目录需纳入备份 |

恢复顺序固定为：OpenBao → Core 数据库 → 各组件权威 → 投影对账 → 能力重新开放。对账完成前不恢复用户可达入口。

恢复不得把 `UNKNOWN` 改写为成功或失败，也不得删除历史 Action、Workflow、Audit、Usage 或 ExternalExecution。

## 5. 容量与性能框架

本节不给数字，只固定必须被测量、被设界并在超限时有确定行为的维度。每个维度在预发布环境取得基线值后写入发布清单。

- BFF 并发连接与订阅：受 Relay 的订阅数、filter 数、帧大小与每身份限流约束，必须在 BFF 侧先行设界并给出明确拒绝，而不是把压力透传给 Relay;
- Core 写事务与严格 reservation 的串行化热点：按 Tenant 加 subject 加 meter 的键测量排队时间；
- Workflow 与 Activity 的并发、心跳间隔与重试放大；
- 单个 Workflow 的 history 事件数与 pending Activity 数，触及门限前必须 continue-as-new；
- 物化 run 的单批项数与失败隔离边界；
- 模型调用的并发与配额交互；
- 文档会话的并发编辑数与保存冲突率。

任一维度超限时的行为必须是确定的拒绝或排队，并映射到 `06-工程基线规范.md` §4 的 `LIMIT` 类 reason code，不允许静默降级或无限等待。

## 6. 必备 Runbook

以下场景在生产发布前必须各有一份经过演练的 runbook，存放于 `docs/runbooks/`：

1. 部署前置不变式校验失败（按 §1 逐组件的排查与修复）；
2. Secret 轮换与紧急撤销，含旧版本销毁顺序与在途执行的处理；
3. 撤权收敛未完成（membership、binding、delegation 三类）；
4. Workflow replay 失败与 Worker 回滚；
5. 投影落后与对账缺口修复；
6. usage 或 audit 缺口的定位与补录边界；
7. 外部副作用结果不明的对账（按组件分别说明可用的查询接缝）；
8. binding generation 切换失败与回滚；
9. 上游升级中止与基线还原；
10. 灾难恢复全流程演练。

每份 runbook 必须写明触发信号、判定依据、可执行步骤、不可执行的动作，以及完成判据。禁止出现"视情况处理"这类无判据的步骤。

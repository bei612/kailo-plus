# ADR-04：本地开发与部署编排

- 状态：已接受
- 日期：2026-09-22
- 决策者：Kailo 实施工程负责人

## 背景

`07-运行与运维基线.md` §2 的目标是让任一工程师在一台机器上跑通一条纵向切片，而不是复刻生产拓扑，并明写「本地可以简化副本数与持久化，不可以简化边界」。要保留的边界来自 `01-工程结构与模块边界.md` §8：Browser 只到达公开入口，BFF 只接受身份投影，管理面不可直达。

`07` §1 的部署前置不变式在本地同样生效，其中若干条是编排层的职责——例如 AgentGateway 的 admin router 不得暴露给 Browser、Agent 或 Tenant admin（`SS-AGW-ADMIN`），Wren 的 runtime 必须位于只有 AgentGateway 可达的网络边界内（`SF-WRN-06`），DocumentServer 的 `ipfilter` 必须精确允许该 Tenant 的 Cells host（`SF-OFF-10`）。这些都要求编排层能表达网络隔离，而不只是把容器跑起来。

`00-实施总纲.md` §6 把编排方式列为 ADR 门禁项，且路线上没有任何 Stage 依赖 Kubernetes 特性。

## 候选方案

**Docker Compose**：单文件描述服务与网络，多个 network 即可表达上述隔离边界，开发者只需 Docker。不提供滚动发布、自动扩缩容与健康驱动的重调度。

**Kubernetes（本地 kind / k3s）**：与生产拓扑同构，NetworkPolicy 表达隔离更严格。代价是每个开发者要跑一套控制面，本地迭代从「改代码重启容器」变成「构建镜像推送重部署」，且路线上目前没有任何能力需要它。

**进程直跑加脚本**：启动最快，但无法表达网络隔离，`07` §1 中属于编排层的不变式会退化成口头约定，违反「不可以简化边界」。

## 决策

**本地与部署统一使用 Docker Compose**，产出 OCI 镜像。不引入 Kubernetes。

- **网络分层**：至少四个 network——`edge`（仅公开入口）、`app`（Core/BFF、Worker、Web 静态服务）、`mgmt`（管理面与 admin router）、`component`（各上游组件 runtime）。跨层可达关系在 compose 文件显式声明，默认不可达。任何服务加入新 network 视同边界变更，按 `AGENTS.md` 的规则评审。
- **发布单元**：`00-实施总纲.md` Stage 0 第 8 项的每个发布单元（Core/BFF、Worker、Web、各 adapter/runner）各自一个镜像、各自一个 tag，compose 文件按 digest 引用，回退即改 digest。
- **上游组件**：按 `04-上游适配与升级.md` 的 baseline manifest 以镜像引入，不从 `.references` 工作树构建。
- **不变式校验**：`07` §1 中属于编排层的条目由一个启动前校验步骤读取 compose 配置核验，校验失败即拒绝启动，而不是依赖人工检查。
- **本地简化的边界**：允许单副本、允许本地卷、允许自签证书。不允许合并 network、不允许把管理面接入 `edge`、不允许关闭任何 `07` §1 的不变式。

## 后果

正面：开发者只需 Docker；网络边界在一个文件里可读可评审；本地与部署用同一套描述，减少「本地能跑线上不行」的类别。

负面：没有滚动发布与自动重调度，发布期间存在中断窗口；单机容量是部署拓扑的上界；跨主机部署需要额外方案。

锁定：Compose 的服务与网络模型。放弃：声明式重调度、水平自动扩缩容、NetworkPolicy 级别的细粒度策略。

## 替换边界

满足任一条件时重新评估：出现多主机部署要求；出现不可接受的发布中断窗口；`07` §5 的容量维度表明单机已成瓶颈。

更换到 Kubernetes 需要改动：compose 文件到 manifest 的翻译、network 分层到 NetworkPolicy 的翻译、启动前校验步骤的读取目标。镜像、digest 引用方式与发布单元划分不受影响，这是按发布单元出镜像的直接收益。

## 不改变的事

本 ADR 不改变 `.design` 的任何权威划分与能力状态。网络边界的形状由 `01-工程结构与模块边界.md` §8 与 `07-运行与运维基线.md` §1 决定，本 ADR 只选择表达它的工具。

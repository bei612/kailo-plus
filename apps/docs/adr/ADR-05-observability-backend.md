# ADR-05：可观测数据的存储与查询后端

- 状态：已接受
- 日期：2026-09-22
- 决策者：Kailo 实施工程负责人

## 背景

`07-运行与运维基线.md` §3 规定了实现侧必须发出什么信号（Governed Action 起讫、外部副作用 dispatch 与观察结果、Workflow 投影写入与落后度量、usage 发布与 committed 确认、对账结果、`07` §1 不变式校验结果），以及什么绝对不能进入信号（业务正文、文件内容、chunk、SQL 行、prompt 与 response、secret 与 token、高基数自由文本）。

`.design/14` 定义的业务可观测视图是受权只读视图，由 Core 从自身权威数据提供，不从监控后端取数。因此本 ADR 选择的是**工程运维信号**的落地后端，不是业务视图的数据源——这两者不得混淆，也不得互相替代。

链路关联以 `operation_id` 为主键贯穿 Core、Worker、adapter 与组件（`07` §3）。

## 候选方案

**OpenTelemetry SDK 加 Collector，后端可替换**：应用侧只依赖 OTLP，后端选择被 Collector 配置隔离，更换后端不改应用代码。多一个进程。

**应用直连某个后端的原生 SDK**：少一跳，但把后端选择编译进每个发布单元，更换后端要改所有服务并重新发布。

**只写结构化日志到文件，事后收集**：最省事，但指标与链路退化成日志解析，`07` §3 要求的「投影落后的显式度量」「缺口计数」无法直接表达为可告警的指标。

## 决策

应用侧**只依赖 OpenTelemetry SDK 并以 OTLP 导出**，后端为 **Grafana 套件**：Prometheus 存指标、Loki 存日志、Tempo 存链路，全部经一个 OTel Collector 接入。

- **应用侧零后端知识**：所有发布单元只配置一个 OTLP endpoint。服务代码中不出现任何后端专有的客户端或字段。
- **标签约束落在 Collector**：Collector 配置一层属性过滤，丢弃不在允许清单内的属性键，作为 `07` §3 禁止清单的第二道防线。第一道防线仍在应用侧——不产生就不会泄漏，Collector 过滤不构成产生它们的许可。
- **关联键**：`operation_id` 作为 trace 的根属性，同时作为日志与指标的 exemplar 关联键。无法透传关联上下文的跳，按 `.design` 对应接缝结论记为不可归因，不以推测补齐。
- **必备信号的表达**：`07` §3 的六类必须发出的信号，每类固定为指标加事件两种形态——指标用于告警与容量，事件用于按 `operation_id` 回溯。投影落后与各类缺口计数一律为指标，不只存在于日志。
- **保留期**：运维信号的保留期独立于 `07` §4 的权威数据保留要求，且不得被当作 audit 或 usage 的替代记录。任何需要长期留存的事实必须已经写入 Core 数据库。

## 后果

正面：更换后端只改 Collector 配置；本地与部署用同一套导出路径；属性过滤有集中的执行点；组件侧只要支持 OTLP 就能接入同一视图。

负面：Collector 是额外进程，它不可用时信号中断；Prometheus 的拉取模型对短生命周期的 Activity 需要额外处理；三个后端组件增加本地拓扑体量。

锁定：OTLP 语义约定。放弃：后端专有的高级查询能力。

## 替换边界

满足任一条件时重新评估：信号量超出单实例 Prometheus 或 Loki 的承载；出现必须由托管服务承担运维的要求。更换只需改动 Collector 的 exporter 配置与仪表盘定义，应用代码不受影响。

## 不改变的事

本 ADR 不改变 `.design` 的任何权威划分与能力状态。`.design/14` 的业务可观测视图仍由 Core 从权威数据提供，不以本 ADR 选择的后端作为数据源；本 ADR 也不放宽 `07` §3 的任何禁止项。

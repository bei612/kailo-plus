# ADR-07：CI 执行环境与受保护分支规则

- 状态：已接受
- 日期：2026-09-22
- 决策者：Kailo 实施工程负责人

## 背景

`03-验证发布与验收门禁.md` §5 固定了十项合并门禁。`07-运行与运维基线.md` §2 要求「提供一条统一命令完成格式、静态检查、contract 检查、迁移演练与追溯检查，与 CI 使用同一入口」。

两条合起来的含义是：CI 不得拥有本地跑不了的门禁步骤。本 ADR 选择执行环境与分支规则，不新增门禁项。

当前仓库没有配置远端（`git remote` 为空）。方案必须在无远端时就能拦住违规合并，并在接入远端后不改变门禁定义。

## 候选方案

**统一入口脚本加 GitHub Actions**：门禁定义在仓库内的脚本里，CI 只负责调用。无远端时用本地 git 钩子调同一入口，接入远端后增加一个调用同一入口的工作流。

**门禁逻辑写在 CI 配置里**：配置即流程，但本地无法复现，违反「与 CI 使用同一入口」。

**只靠约定与人工评审**：无执行成本，但十项门禁中有八项是机器可判定的，交给人是浪费且不可靠。

## 决策

**门禁定义在 `tools/check.sh`**，本地与 CI 调用同一个入口。

- **入口结构**：`tools/check.sh` 按 `03-验证发布与验收门禁.md` §5 的十项分为十个子步骤，每步独立可单独调用（`tools/check.sh <step>`），全部失败以非零码退出。`tools/check-docs.sh` 成为其中「只改文档」的快路径，保持现有行为与独立可执行性。
- **增量与全量**：默认按变更范围选择需要执行的子步骤，`--full` 强制全部执行。受保护分支上一律全量。
- **执行环境**：容器内执行，镜像由本仓库定义并按 digest 固定，本地与 CI 使用同一镜像。镜像必须包含 **Go ≥ 1.25.4**——Temporal Go SDK `v1.48.0` 的 `go.mod` 声明该下界，低于它时 Go 会静默下载并切换工具链，导致本地与 CI 实际使用的编译器版本不可控。这保证「本地通过 CI 不通过」只会来自变更本身。
- **CI 平台**：GitHub Actions。当前无远端，因此先以本地 `pre-push` 钩子调用 `tools/check.sh --full` 作为执行点；接入远端后增加一个工作流调用同一命令，门禁定义不变，本地钩子降级为快速反馈手段。
- **受保护分支**：`main` 禁止直推，只接受经评审的合并；合并前 `tools/check.sh --full` 必须通过；历史只追加，禁止强制推送。无远端期间这三条由本地钩子与评审约定执行，接入远端后改由平台强制。
- **门禁不得跳过**：不提供跳过开关。某项门禁在当前 Stage 无适用对象时（例如尚无 Workflow 时的 replay 检查），该步骤输出「无适用对象」并通过，而不是被注释掉——这样它在首次出现适用对象时自动生效。

## 后果

正面：门禁定义与代码同仓同版本；本地可完整复现 CI；无远端时也有执行点；接入远端只是增加一个调用点。

负面：本地钩子可被绕过（`--no-verify`），在接入远端前分支保护是约定而非强制；容器内执行使单次检查启动变慢；十步入口需要随 Stage 推进持续补全实现。

锁定：以脚本为门禁定义的形式。放弃：使用 CI 平台专有编排能力（矩阵、缓存策略）来组织门禁逻辑。

## 替换边界

更换 CI 平台时重新评估工作流文件，`tools/check.sh` 与执行镜像不受影响。若统一入口的全量执行时间长到影响迭代，重新评估增量判定策略，而不是削减门禁项。

## 不改变的事

本 ADR 不改变 `.design` 的任何权威划分与能力状态，也不改变 `03-验证发布与验收门禁.md` §5 的十项门禁内容——它只固定这些门禁在哪里定义、由谁执行。
